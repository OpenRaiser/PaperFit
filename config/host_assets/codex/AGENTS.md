# PaperFit host integration

PaperFit's structured visual closed loop is required: inspect actual rendered pages for diagnosis; after each coherent repair candidate, recompile, rerender and actually inspect every current physical page before accepting it or selecting the next repair; inspect every final physical page before acceptance. Record actual visual observations and keep/revise/rollback decisions. The multimodal host executes this PaperFit workflow. Auxiliary API vision supplements it; visual feedback itself is mandatory. A clean build, exact page count or final evaluator score does not substitute for candidate-level visual verification.

A candidate can contain a batch of related edits. Finish that batch before visual verification; inspect every page at readable scale and zoom into repaired objects or suspected regressions. Keep verified progress and continue when preservation/template checks pass and no confirmed regression is introduced; unchanged original defects or an ineffective sub-edit do not require discarding successful repairs. Correct or selectively revert a harmful edit where separation is reliable, then rebuild, rerender and inspect all pages of the combined result. If separation is unsafe, restore the smallest safe checkpoint and preserve previously verified rounds. Intermediate retention is distinct from final completion; do not change guarded-route thresholds or invent a PASS.

Use the discoverable `paperfit` skill for LaTeX paper layout requests. Codex is the host: it reads evidence, edits source, compiles, renders, and judges the result. PaperFit supplies tools and layout expertise.

Treat PaperFit's proposed repairs as advice: **请你看看这是否是对的**. Check the current source/PDF and the actual object before accepting, adapting or rejecting a suggestion. An executable candidate is not a quality judgment. Plan requested pages, readability and complete visible content together; related repairs can be combined when their effects are verified.

The user's authorization determines Codex's native editing scope. Repair any relevant project source, include, local style/class or configuration with normal host tools; combine edits, reorganize related files, and use alternatives outside PaperFit's tool menu when needed. Do not ask again for routine authorized edits or acknowledge every individual finding. PaperFit tools support the host rather than limit its capabilities.

`human_review`, `approval_required` and unsupported-operation statuses belong to the optional guarded batch. The current host should inspect the uncertainty and continue an independently anchored native repair; these statuses do not inherently require another human's approval. Actual scientific-content loss, violation of user template requirements and stale or fabricated build evidence remain unacceptable. Do not manufacture an automated PASS when a checker cannot cover a rewrite.

After `paperfit-install --target codex`, the entry is `~/.agents/skills/paperfit/SKILL.md`. For one paper use `paperfit-install --target codex --scope project` from its root; the entry is `.agents/skills/paperfit/SKILL.md`. Start a new session, then ask naturally or use `$paperfit`.

Inspect with `paperfit check-visual --main "<root.tex>"`, and open page images with the host image tool. Analysis stops at findings. An authorized repair can use normal host edits; the optional typed batch is `paperfit fix-layout --main "<root.tex>" --apply --max-rounds 3`. Preserve academic content and object labels; recompile and inspect all final pages before delivering.

Verify each coherent candidate with a fresh build, fresh rendering and inspection of every physical page before accepting it or choosing the next repair; inspect all final physical pages after the last source change. Do not force the full tool sequence after every intermediate edit. Optional API vision can support important uncertain changes; it need not read the whole PDF after every small edit. Correct or restore partial edits after a tool failure and keep a failed preparation separate from a new measured layout candidate. Report unmet goals and missing evidence honestly; a batch limit or clean detector is not completion.

No custom agent registration, slash prompt registry, model change, or global AGENTS.md replacement is needed. An existing custom role may delegate work, but does not define the workflow. `paperfit root` locates bundled expertise and scripts; they are not in the paper project.
